# Публикация защищённых правил sync_v3 — инструкция владельцу

**Статус:** только для контролируемого пилота, не включать новую синхронизацию в приложении автоматически. Проверенный тестовый вариант хранится отдельно от основного сайта.

## До изменения Firebase

1. Откройте **Firebase Console → Firestore Database → Rules** проекта `riveria-sanasto-community-test`.
2. Скопируйте **весь** текущий текст действующих Rules и сохраните отдельно. Не публикуйте исправления наугад.
3. Сверьте его с ранее предоставленным исходным набором правил от 2 ноября 2026 года. Если кто-то менял правила после этой даты — **остановитесь**, подготовьте новый merge.
4. Наиболее безопасный путь: добавьте содержимое `staging/firestore.rules.additive.txt` **внутри** `match /databases/{database}/documents`, непосредственно **перед** завершающим `match /{document=**} { allow read, write: if false; }`.
5. **Не вставляйте** второй `rules_version` или второй `service cloud.firestore`. Файл additive — это только функции и новые `match`.
6. Перед нажатием Publish убедитесь, что `users`, `settings`, `libraries`, их функции и условия остались неизменны. В идеале пришлите текст или скриншот добавленного фрагмента для проверки.
7. `staging/firestore.rules.pilot.test` — полный образец **только при точном совпадении** исходных правил со старым снимком. Не копируйте вместо текущих правил, если есть расхождения.
8. После Publish проверьте зелёное подтверждение публикации и отсутствие ошибок синтаксиса. Затем НЕ создавайте вручную документы в `sync_v3`: приложение ещё не переключено на новый режим.
9. Проверку доступа по Firestore Simulator повторите для `sync_v3/<твой UID>/events/<test event ID>`. Без существующего документа GET владельца может дать DENIED/NOT_FOUND: это не равнозначно проблеме правил; для положительной проверки записи нужен отдельный тестовый клиент и корректный event body.
10. Прежние Google Drive Sync и резервные копии сохраняются без изменений до завершения пилотного переноса.

## Обратимость

- Если правила опубликовались с ошибкой или возникли отказы доступа в существующих разделах, верните сохранённые **предыдущие** Rules через историю версий Firebase, затем повторно проверьте доступ.
- Новые `sync_v3` пути без клиентского кода не создают документов сами по себе.
- Новый модуль админки не запускается. В пилотной версии **нет** разрешения на `site_admin`.

## Проверки, выполненные до публикации

GitHub Actions запускает тесты через отдельный Firebase Emulator с проектом `demo-sanastoyhteiso`; это никогда не обращается к рабочему Firebase. Подготовленный набор правил проверен для владельца, чужого UID, гостя, некорректных событий и существующих коллекций.

**Публичная ветка GitHub не является безопасным местом для личных JSON-бэкапов, токенов, паролей, закрытых логов, электронных адресов или сервисных ключей.**
