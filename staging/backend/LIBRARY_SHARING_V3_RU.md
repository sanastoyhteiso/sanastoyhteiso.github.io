# Sanastoyhteisö 3.0 — библиотеки и безопасный обмен

## Выполнено в отдельном тестовом v3-classic

Только в отдельном тестовом репозитории. Основной Sanastoyhteisö и реальная Firebase не затронуты.

Раздел «Библиотека» имеет привычный внешний вид и остаётся доступным всем. В нём две явно вымышленные учебные библиотеки. Пользователь может просмотреть их слова, добровольно подписаться, использовать слова в карточках и тестах, отменить подписку без стирания результатов.

Можно создать собственную подборку из только что добавленных на этом тестовом сайте личных слов, выгрузить JSON и передать файл другому браузеру. Импортируемая библиотека появляется в каталоге, но не подписывается автоматически. Передаются ТОЛЬКО поля слов fi/ru/en/cat, название, категория, ID и версия. Не экспортируются результаты, избранное, оценки, email, UID, заметки аккаунта и OAuth. Новый локальный ID каждого слова привязан к ID библиотеки, чтобы исключить смешивание результатов.

Схема обмена — версия 1, маркер sanastoyhteiso-v3-public-library. До 100 слов и 80 000 символов в JSON, проверка ID, языка, длины полей, отсутствия дублей финских слов, отказ при неизвестных/приватных свойствах. Повторный импорт одинаковой коллекции идемпотентен; попытка заменить библиотеку с тем же ID другим содержимым запрещена. Повреждённые локальные данные сохраняются для диагностики, не перезаписываются пустым списком.

Отдельное хранилище только с префиксом rs_v3_classic_synthetic_only__. Реальные учётные записи, данные Google Drive и существующего Firebase не используются. Браузерная CSP запрещает сетевые подключения.

Это пока РУЧНОЙ обмен JSON-файлом, а НЕ публикация по ID в интернете. ID показан как будущий идентификатор. UI не должен обещать настоящую общую облачную библиотеку до независимого Firebase.

## Будущая серверная архитектура — план, не реализована

Требуется новый Firebase-проект, отличный от riveria-sanasto-community-test, отдельные test Auth и Firestore. Ни одного правила/документа в существующем проекте не менять.

В новом проекте планируются:
1. Библиотеки: метаданные с ownerUid, публичным названием, visibility, category, version, wordCount, updatedAt и checksum. Проверка роли владельца серверными Security Rules.
2. Версионированные публичные релизы: только безопасные слова и каталожные поля, без личных результатов и Google токенов. Новая версия никогда сама не удаляет личные достижения или сохранённые слова подписчиков.
3. Подписки по uid: доступ чтения/записи только владельцу uid, явное принятие новой редакции коллекции, безопасное отключение.
4. Поиск общего каталога и подключение по ID с ограниченными запросами; приватные библиотеки никогда не открываются без разрешения.
5. Админ-панель под «Данные → Настройки сайта» только после реальной серверной проверки прав. Обычные «Данные» и «Библиотека» доступны всем.

Пока схема — подготовительный дизайн, а не развернутые Firestore коллекции. Для настоящего обмена обязательны проверка Security Rules (включая чужие UID), отдельный пилот с вымышленными аккаунтами, синхронизация IndexedDB с Firestore, тест с несколькими устройствами, проверка старого Safari, новая независимая резервная копия перед миграцией и отдельное согласование владельца.

Тест: staging/tests/classic-library-sharing.test.cjs. UI-регрессия: staging/tests/classic-v3-ui.test.cjs. Серверный guard: staging/backend/v3-staging-project-guard.js. Ничего из этих файлов не должно включаться в рабочий main преждевременно.
