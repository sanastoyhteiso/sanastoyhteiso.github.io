# RUN-035 — проверяемая закрытая копия V3 → Google Sheets: безопасный контракт

**Дата:** 05.11.2026. **Текущая реализация:** чистый офлайн-модуль `v3-backup-codec.js` (без сетевых вызовов), тест `release-checks/v3-backup-codec.test.cjs`, CI `.github/workflows/release-v3-preflight.yml`. Модуль не включён в основную страницу, ничего сам не загружает и не восстанавливает.

## Важное разграничение

- `create` создаёт только **локальный план** строк и манифеста. Результат `complete:false`, `restoreTested:false`.
- `readBack` проверяет только **полученные извне строки**, в памяти, без записи: UID, snapshot ID, количество записей в 4 секциях, отсутствие дубликатов, полноту строк и SHA-256. Возвращает `verifiedOffline:true`, `liveSheetsVerified:false`, `canAutomaticallyRestore:false`.
- Контрольная сумма SHA-256 обнаруживает случайную порчу и несоответствие сохранённому манифесту; **не является** электронной подписью и не доказывает, что копию создал доверенный сервер. Подлинность обеспечивают роли, неизменяемая история и отдельная проверка источника.
- Сфера копии — только `v3-shadow-state-only`: `scores`, `words`, `favorites`, `finds`. Это **не полная копия** всех Firebase событий, Auth пользователей, Google Drive, личных документов, старых исторических ответов или словарной публичной базы.

## Обязательная будущая цепочка в доверенной среде

1. Сверить выбранный Firebase-проект, текущие Rules/права, владельца копии и допустимость действий с персональными данными. По умолчанию использовать **READ-ONLY** Firestore экспорт и минимальный доступ, не использовать доступ администратора для публикации пользовательских ответов.
2. Для теста использовать **синтетический** TEST UID и fixtures. Данные реальных учеников не переносить в GitHub, сообщения ChatGPT, открытые таблицы, публичные логи и тестовые API. Сначала юридическая/техническая проверка обработки персональных данных.
3. В доверенном runner/скрипте сформировать фиксированный snapshot в согласованной версии, получить строки `create()` и manifest. Сохранить в **новую закрытую** Google Таблицу только через `valueInputOption=RAW` (никакого `USER_ENTERED`; защита от формул), без overwrite действующих копий. Секреты — только в безопасном хранилище исполнителя, не в Pages/публичном PR.
4. После завершения загрузки **повторно прочесть строки из самой Таблицы**; выполнить `readBack()` и сверить проект/UID/снимок, SHA, число строк/секций. Сохранить отдельную закрытую контрольную запись (время, hash, число строк, результат). При расхождении: FAILURE, исходные данные не менять.
5. В изолированной TEST базе/фикстуре выполнить обратное восстановление **в новый namespace**, прочитать результат, сверить нормализованное состояние и контрольную сумму. Только после этого `restoreTested` можно считать подтверждённым в доверенном журнале — не путать с offline тестом.
6. При изменениях после снятия снимка — придерживаться explicit reconciliation планов: snapshot + newer immutable events. Не откатывать более свежие учебные ответы или личные слова ученика без осознанного корректного conflict-review.
7. Хранение/ротация: дата, источник, независимая учётная запись владельца копии, права доступа, ожидаемый retention, предупреждение об ошибке, контроль доступности Google Sheets и проверяемый журнал восстановления. Не удалять старую копию, пока новая не проверена.

## Что уже проверяют CI-тесты

- Русский, финский, английский текст в JSON; сохранение структуры четырёх секций.
- Разные UID/snapshotId, пропущенная или дублированная строка, подмена JSON, неподдерживаемые поля/ключи, SHA mismatch, отсутствие WebCrypto.
- `v3-backup-codec.js` разбирается JavaScript-парсером без современных ES2020 операторов; `node:crypto.webcrypto` используется лишь в тестовом Node runner.
- Манифест никогда не выдаёт ложный `complete=true` или `restoreTested=true` до независимой доверенной проверки.

## Открытые технические вопросы — отдельные gated задачи

- Техническая схема исполнения приватного Google Sheets backup на бесплатном Firebase Spark без передачи привилегированных ключей в браузер (возможны Apps Script/trusted runner, но **не объявлять** выбранным без отдельного security review и подтверждённых прав). Важно: реальная автоматизация резервного копирования должна работать по расписанию и сообщать об ошибках, а не просто показывать кнопку.
- Полный источник истины: immutable Firestore `sync_v3` events + baseline, а не только shadow state. Нужен полный manifest для events, версий/public dictionary, конфигурации и legacy history; он должен проверяться отдельно. Схема текущего codec не заменяет полный backup.
- Различать TEST (`sanastoyhteiso-v3-development`) и будущую production (`riveria-sanasto-community-test`) в trust boundary; никогда не подменять конфигурацию только ради «работает».
- Отдельный релизный GO владельца до production cloud actions, оплаты, миграции или реального переключения сайта.

**Итог RUN-035:** воспроизводимый офлайн-контракт готов/проверяем CI; задача NEW-001 по живой private Sheets backup и восстановлению остаётся открытой.
