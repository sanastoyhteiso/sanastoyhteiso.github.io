# RUN-043 — лимиты TEST резервного копирования и отказ без частичной фиксации

**Дата:** 05.11.2026. **Стадия:** NEW-001 / A, G, H, I. Только DRAFT release PR #9, никаких реальных Google API вызовов или запусков триггеров.

## Что изменено

В `backup-v3/apps-script/Backup.gs` добавлены **жёсткие защитные ограничения тестового пилота для одного явно выбранного UID**:

- Не больше **300 персональных Firestore документов** (events, words и необязательный baseline суммарно). Число проверяется после каждой страницы чтения; превышение прекращает операцию до создания Google Sheet.
- Не больше **1200 строк Sheets**, включая заголовок. Проверка выполняется непосредственно перед первым вызовом создания новой приватной таблицы.
- Не больше **210 секунд** с начала запуска. Время проверяется до/после Firestore запросов, до создания Sheet и перед каждым дальнейшим RAW write/read и записью manifest. При превышении обработка останавливается; значение `complete=true` не фиксируется.
- Блокировка `LockService` удерживается до завершения всей Promise-цепочки, затем освобождается и метка времени сбрасывается даже при отказе; отказ не запускает повторный экспорт автоматически.
- Границы фиксированы в коде и не могут быть расширены через Script Properties, незнакомые URL или конфигурацию ученика.

**Важно:** если отказ случится уже после создания новой приватной Sheet, она может остаться частично записанной. Однако она **не получает подтверждённый manifest** и не считается готовой копией. Автоматическое удаление такой записи не предусмотрено, чтобы исключить случайное удаление полезных данных. Нужны будущие индекс отказов, retention и уведомления.
