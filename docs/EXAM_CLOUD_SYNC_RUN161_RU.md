# RUN-20261108-161 — межустройственная синхронизация 40-вопросного экзамена

## НАЧАЛ — 08.11.2026 Europe/Helsinki

Владелец находится на **15/40**, **14 заданий уже пройдены** на одном устройстве, а на телефоне при входе в тот же аккаунт экзамен начинается с 1/40. Он просит автоматическую, защищённую от потери данных синхронизацию через аккаунт между устройствами, позднее для всех других учебных тестов.

**Аудит:** RUN159 сейчас хранит полный порядок 40 вопросов, ответы, индекс, языковое направление, финальный результат **только в per-UID localStorage**. Firebase Google Authentication подключён (compat SDK 8.10.1), `RS_FAMILY.uid`, `RS_FAMILY.getToken()` доступны, Firestore SDK загружен. Однако текущие **опубликованные** production Firestore Rules проекта `riveria-sanasto-community-test` НЕ прочитаны; GitHub содержит только исторический/подготовленный контракт (документы `docs/ENABLE_V3_PRODUCTION_FIRESTORE_RU.md`), а существующая V3 `sync_v3` разрешает строго определённые учебные события, НЕ состояния экзамена. Прямая запись в `users/{uid}`, `settings/{uid}`, `sync_v3` в обход проверок недопустима. Google Drive sync у `RS_COMM` требует отдельного OAuth-разрешения и действует только при подключении Drive на каждом устройстве; не обеспечивает автоматически облачное продолжение экзамена.

**Безопасная цель:** выделенный закрытый документ `mock_exam_progress_v1/{uid}`, доступный только владельцу с подтверждённой почтой в выбранном Firebase; сохранять snapshot строго валидной попытки, тот же порядок 40 вопросов, выбранное направление, ответы и текущую позицию. Новый ES5 модуль `exam-cloud-run161.js` должен обрабатывать сетевые ошибки, разрешения, конфликт разных попыток, отсутствие связи, условную/транзакционную запись; локальный snapshot всегда остаётся первичным резервом. Никогда не заменять **14 ответов** пустой попыткой, случайно открытой на телефоне. Перед первым cloud write обязательно прочитать текущее состояние сервера. При обнаружении двух несовместимых непрерывных попыток нельзя автоматом затирать ни одну — нужен выбор владельца и локальная защита обеих. По успешной синхронизации облачный прогресс автоматически подхватывается на втором устройстве, только при входе в **один и тот же verified UID**.

**Политика выпуска:** сначала изолированные тесты Firestore rules на синтетических пользователях, фейковые браузерные сценарии first device 14/40 -> phone 15/40, auth/permission denied, conflict и rollback; подтвердить production deployed rules read-only в Work, сделать additive changes только после отдельного review/разрешения владельца, никаких тарифов/неизвестных IAM. До этого держать изменение в DRAFT PR и **не менять production main**, чтобы не ухудшить сохранение существующих 14 ответов. Production Firebase и реальные пользовательские данные не читать/писать в рамках подготовки. Резерв `backup/pre-exam-cloud-sync-run161-20261108`.

**Не делать:** удаление localStorage, изменение счета «Выучено», изменение V3 sync, попытка облачной отправки до авторизации и подтверждения Rules, логирование JWT/UID/частного payload, хранение идентификаторов в публичном репозитории.
