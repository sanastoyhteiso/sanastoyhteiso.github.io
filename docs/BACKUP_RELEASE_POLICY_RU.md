# ПОЛИТИКА НЕПРЕРЫВНОГО РЕЗЕРВИРОВАНИЯ И ВОССТАНОВЛЕНИЯ — 17.11.2026
Владелец: Илья Дмитриев. Касается обоих проектов отдельно: Sanastoyhteisö 3.0 и Velar Dream Records.

## Непременное правило для каждого будущего RUN/PR/релиза
1. Перед существенным изменением создать доступную точку восстановления исходников и, если меняется модель данных, отдельную защищённую копию соответствующих записей.
2. После существенного изменения/новой ветки/PR/релиза обновить: docs/RECOVERY_CHANGELOG_RU.md, START_HERE_DISASTER_RECOVERY_RU.md, карту модулей/схем и manifest backup snapshot. Внести дату UTC, SHA, PR, изменённые файлы, миграции данных и проверки.
3. Проверить, не добавлены ли новые внешние хранилища, сервисы, файлы, collection paths, Storage buckets, OAuth providers, журналы, медиа, секреты. Если добавлены — расширить backup/export и restore инструкцию ПЕРЕД объявлением копии полной.
4. При публикации обновить backup GitHub production SHA и отметку об успешном развёртывании; ветка сама по себе не production.
5. Снимать свежие версии регулярно (ежедневно/через день по выбору владельца), а также до и после рискованных изменений. Не удалять предыдущую подтверждённую копию при создании новой.
6. Устанавливать label: CODE_ONLY / PARTIAL / FULL_RESTORED_TESTED. Помечать COMPLETE только если реально экспортированы все согласованные хранилища, проверены hashes, отсутствуют пропуски и тестовый restore прошёл.
7. Не сохранять персональные данные в публичном GitHub или общедоступных Actions artifacts; для защищённого хранения использовать encryption и приватный Drive, ключ хранить отдельно.
8. После тестов внести в журнал НАЧАЛ/ЗАВЕРШИЛ, использованные команды, контрольные суммы и реальные ссылки на Drive. Если тест не прошёл — записать FAILED и причину, не замалчивать.

## Владельцу на случай исчезновения всего
Каждый ZIP обязан содержать START_HERE_DISASTER_RECOVERY_RU.md и docs/RECOVERY_CHANGELOG_RU.md. Новый ИИ получает один архив, не должен искать наши чаты, email или историю. Восстановление начинается с прочтения этих документов и manifest.

## Обязательные границы
GitHub-only снимок не включает Firestore/Auth, внешние media, Google Drive/Sheets, Cloudflare/D1, localStorage/IndexedDB других устройств, secrets. Это не повод не сохранять код: для каждого недоступного слоя статус указан отдельно.

## Архивная дисциплина
Версии датируются и не перезаписываются; контроль SHA-256; checksum внутри ZIP; сохранять копию в Google Drive velardream@gmail.com → WEBSITE_BACKUPS → Backup → папка соответствующего сайта; скачивать вторую копию на своё устройство и при возможности на офлайн-носитель.
