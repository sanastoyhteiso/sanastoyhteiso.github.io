# RUN-20261105-062 — блокер в черновой V3 сверке с облаком: ложный статус после upload failure

**Дата:** 2026-11-05, Europe/Helsinki. **Статус: BUG CONFIRMED BY SOURCE / CODE CHANGE BLOCKED BY TOOL / NO CI.** Этап G/H, NEW-009. Только DRAFT TEST PR #3, основная версия и Firebase не затронуты.

## Проверенный дефект в текущем исходнике

Файл: `v3-unified-preview/v3-sync-release.js`, DRAFT TEST PR #3. Текущий SHA файла `39ef392d1c45f2c36a9ec2a9528fd34affdb5b9a`; TEST HEAD `f3a99c62d2b6d5f9f7475fcee2400953749ea0f5`.

В `refresh()`:
1. `engine.upload().catch(function(){return null;})` **подавляет отказ загрузки** локальных событий на сервер.
2. Далее `engine.refresh()` читает и сливает данные обратно с текущим shadow, что может быть корректно и не удаляет очередь.
3. Независимо от исхода upload метод всегда сообщает `Данные V3 сверены с облаком.` и возвращает `true`, даже если локальные ответы ещё находятся в IndexedDB и **их запись в облако не подтверждена**. Это ложное обещание, потенциально влияющее на действия владельца при смене устройства.
4. `orderly()` возвращает свой `job` раньше, чем его внутренний promise `queue` уменьшает `queued`; поэтому непосредственная проверка `if(queued===0)apply(r)` в `refresh().then(...)` может не применить успешно прочитанный снимок к UI. Это вывод из порядка микрозадач Promise, требует отдельного runtime regression.

## Безопасный предполагаемый fix (не выполнен)

- Сохранить локальные события и действующий механизм `engine.refresh()`/shadow reconciliation, **не сбрасывать очередь** при upload failure.
- Запоминать факт failed upload в пределах конкретного вызова; после server-read/merge проверить `r.pending`. При непустой очереди или failed upload возвращать `false` и честное переведённое FI/RU/EN сообщение «Не все изменения отправлены в облако» вместо успешного статуса.
- Дождаться выполнения serial `queue` и очистки счётчика, прежде чем вызывать `apply(r)`, и повторно проверить UID/session epoch для предотвращения переноса UI из старого аккаунта. Если apply невозможно — fail closed.
- Не превращать `false` в потерю событий. Без реальных Firebase API изменять только DRAFT TEST. Добавить изолированный runtime тест: успешный upload+readback; denied/offline upload+успешный readback; r.pending не пуст; UI apply после окончания очереди; смена UID во время refresh; отсутствие утечки сообщений старого аккаунта.
- Обновить source asset cache в `v3-unified-preview/index.html` и `sw.js`; прогнать exact-head GitHub Actions по тестовому PR #3. Не объявлять bug fixed без этих результатов.
