# RUN-MYFINDS-EDIT-DELETE-20261115 — редактирование и удаление личных слов

Дата: 15.11.2026. Репозиторий: `sanastoyhteiso/sanastoyhteiso.github.io`. Основная ветка `main` не менялась в ходе разработки до успешных проверок.

## НАЧАЛ — запрос владельца
Пользователь добавляет новые слова через плюсик в личный словарь/«Мои находки». При записи на слух ошибается в финском слове или переводе и хочет вернуться позже, исправить и сохранить. Кроме того, прежнее удаление иногда показывало отказ. Задача: полноценное редактирование и надёжное удаление с сохранением личной истории и безопасной синхронизации между устройствами, не меняя общую библиотеку.

## Причины найденного поведения
1. В `app.js` `data-action="delete-word"` при включённой V3 намеренно возвращал сообщение: «В V3 удаление пока отключено: требуется безопасная история версий».
2. В `v3-sync-release.js` панель «Мои находки V3» могла только добавлять или снимать отметку `collection_set`. Кнопка «Убрать из находок» не удаляла само собственное слово из пользовательского словаря.
3. `v3-sync-core.js` отвергал любые изменённые FI/RU для идентичного W_ ID. Это защищало от незаметного конфликта устройств, но блокировало осознанное исправление.
4. Действующие правила Firestore для `sync_v3` допускают неизменяемые `word_upsert` и `collection_set`, но не допускают отдельные `word_delete` события. Простое удаление массива клиента рискованно: старые события могут его восстановить.

## Реализовано в ветке
- **V3, персональные W_:** форма «Редактировать» в списке сохранённых находок: исправление финского написания, русского перевода, изменение раздела/заметки.
- **V3, общие T/M/P/H:** доступна смена категории и заметки без возможности изменять общий термин и перевод.
- **V3, два разных действия:** «Убрать из находок» (снимает отметку) и «Удалить слово» (только владелец W_ слова). Все действия требуют подтверждения или явного сохранения.
- **V3, защита истории:** каждая редакция создаёт новый неизменяемый `word_upsert` в уже разрешённом формате. В поле `catRu` события добавляется техническая ссылка `Мои слова|edit:E_<32 hex>` на предыдущее событие; при материализации она очищается из отображаемого `catRu`. Редакция без совпадающего родителя отвергается как конфликт, и старая история сохраняется.
- **V3, удаление без потери записи:** `word_upsert` с `Мои слова|delete:E_<32 hex>` образует tombstone `deleted:true` с прежними FI/RU, не исчезающий из облачной истории/IndexedDB. UI скрывает его из списка, локальные данные содержат отметку удаления. Старое событие создания не может автоматически восстановить удалённое слово. Восстановление допустимо только с новой явно привязанной редакцией.
- **V3, стабильный ID:** исправление слова не меняет его идентификатор, поэтому данные учёбы и избранного остаются привязанными к нему.
- **V3, конфликты:** редактирование против устаревшей версии отвергается, а не перезаписывает чужие изменения. Для `collection_set` временные метки строго возрастают даже при быстрых действиях.
- **Legacy (если V3 не включена):** кнопка «Редактировать» и форма исправления для локальных `L...` слов. Удаление записывает и tombstone, и новый список; при ошибке записи пытается восстановить прежнее содержимое. Сохранение проверяется до отображения успеха.
- **UI:** в активной V3 старый блок личных слов с намеренно заблокированной кнопкой удаления скрыт. Остаётся актуальная панель «Мои находки V3» с редактированием/удалением.
- **Офлайн:** `index.html` и `sw.js` загружают версии `my-finds-edit-20261115-1` / `word-edit-20261115-1`. Кэш обновлён до rc44. Другие ранее добавленные разделы не менялись.

## Тесты и ограничения
- Новый `release-checks/my-finds-edit-delete-20261115.test.cjs`: создание, редактирование, конфликт, удаление-tombstone, восстановление и ограничения общих терминов.
- В `release-checks/v3-unified-browser.test.cjs` добавлен сквозной сценарий: собственное слово → редакция → синхронизация → удаление → повторная загрузка, а также снятие отметки с общего термина.
- Новые проверки включены в обязательный GitHub Actions `release-v3-preflight.yml`. Старый калькуляторный тест перестал зависеть от конкретной версии офлайн-кэша.
- Формат событий сохраняет строгий список полей действующих правил Firestore — отдельной смены правил безопасности не требуется **при условии**, что реально опубликованная версия правил соответствует изученному производственному блоку. Права реального аккаунта и фактическая работа Firestore должны быть проверены на живом сайте после публикации.
- Противоречащие изменения с двух устройств **не сливаются автоматически**. Это сделано намеренно. Прежние офлайн-копии клиента до обновления могут не понять новые редакции и должны получить свежие JS-файлы через SW.
- НЕ выполнялось редактирование/удаление реальных слов пользователя; использованы только синтетические тестовые данные.
