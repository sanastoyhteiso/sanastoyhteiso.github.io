# RUN-143 / NEW-021 — общий мониторинг технических сбоев

Статус: подготовлено в DRAFT PR №15. Это **не означает реальное подключение**. Рабочие Firebase/Google Drive/Sheets/биллинг не менялись.

## Система

- Браузер: monitoring-client.js, только пользовательский opt-in, не более 10 локальных событий в очереди, только белый список технических кодов, версия приложения и грубый класс браузера. Не передаются ответы, имена, UID, email, URL, тексты ошибок, стек или медицинские данные.
- Сервер: monitoring/worker/index.mjs — Cloudflare Worker с криптографической проверкой Firebase ID JWT (RS256, Google JWK, aud/iss/exp/iat/auth_time/email_verified) строго проекта riveria-sanasto-community-test; origin и schema allowlist; HMAC для псевдонимных квот без сохранения UID, 24 события на пользователя/час и 1000/сутки глобально, дедупликация ID.
- Хранилище: отдельная закрытая Cloudflare D1 с schema.sql, срок хранения технических записей 7 дней. Никакого прямого Firestore telemetry write с браузера.
- Админка: admin/monitoring-admin.js, повторная серверная проверка admin=true и агрегаты по видам/браузерам. До проверки всех устройств не показывать статус «ОК»; real counts не равны гарантии покрытия.
- Cron каждые 5 минут проверяет запись/чтение D1, но не притворяется, что проверил приход событий от пользователей.

## Действия в авторизованном ChatGPT Work (без локальной CLI на старом Mac/iPhone)

1. Открыть https://dash.cloudflare.com/ в Work Cloud Browser. Войти в собственный Cloudflare Free или создать Free. Не переходить на платный тариф без отдельного разрешения.
2. Создать одну новую пустую D1 с именем sanastoyhteiso-v3-telemetry и импортировать только monitoring/worker/schema.sql. Исторические файлы/Firestore/Sheets НЕ импортировать.
3. Создать отдельный Worker из monitoring/worker/index.mjs; связать D1 как DB. Использовать monitoring/worker/wrangler.toml.example как шаблон, реальный database_id и приватный wrangler.toml не публиковать.
4. Задать FIREBASE_PROJECT_ID=riveria-sanasto-community-test, секрет HASH_KEY — криптографически случайная строка не короче 32 символов; хранить исключительно в секрете Cloudflare, никогда в GitHub/чат/логах. Добавить Cron */5 * * * *.
5. Запустить TEST-синтетику: подписанный JWT → успешная запись 201 и D1 receipt; повтор → 200 duplicate; чужой Origin → 403; истёкший/чужой JWT → 401; чужие поля → 400; обычный пользователь читает summary → 403; admin=true → 200. Проверить cron readback и лимит 429.
6. Только после реального HTTPS endpoint и отрицательных тестов обновить config.js (RS_TELEMETRY_CONFIG.enabled=true, endpoint=реальный workers.dev), index.html/sw.js cache version, пройти 3/3 CI и GitHub Pages. Не угадывать URL.
7. На iPhone и втором устройстве пользователь отдельно разрешает техническую диагностику в разделе «Данные». Отправить тестовую allowlisted ошибку, увидеть её в защищённой админке, проверить отказ обычному аккаунту, отсутствие PII в D1, зафиксировать время и результат. Не считать ноль событий доказательством безошибочности.
8. Только после настоящего readback отметить NEW-021 CONNECTED и закрыть RUN в GitHub. До этого оставить статус BACKEND_NOT_DEPLOYED и не выводить ложную зелёную сводку.

## Откат

Отключить RS_TELEMETRY_CONFIG.enabled в отдельном PR; при необходимости выключить Worker. Не удалять пользовательские аккаунты, учебные события или резервные файлы. Услуга Cloudflare Free имеет лимиты, при превышении даёт отказ; тариф Firebase Spark не меняется.

**Отдельные незакрытые задачи:** реальное закрытое восстановление Google Sheets (NEW-001), проверка исторической learned отметки (NEW-018) и полноценная двухустройственная приёмка. Глобальный мониторинг не является резервным копированием.
