# Восстановление двух сайтов — этап 1 (17.11.2026)

НАЧАЛ: подготовка отдельной ветки для ручного создания снимка исходных файлов без вмешательства в production.

## Что реализовано в ветке
- `.github/workflows/recovery-code-snapshot.yml`: ручной GitHub Actions workflow.
- `tools/create_code_snapshot.py`: проверяемый ZIP **только Git-tracked файлов** текущего commit с JSON-манифестом и SHA-256.
- Архив можно скачать из Actions artifacts после публикации ветки и успешного workflow; срок хранения артефакта 90 дней.
- Архив не включает секреты, файлы вне git, базы данных, внешние медиа или аккаунты.

## До полной кнопки «Резервное копирование» необходимо
1. Создать **доверенный серверный** export endpoint, аутентифицирующий владельца через Firebase ID token и серверную проверку owner role. Не экспортировать пользовательские данные клиентским JS и не хранить служебные ключи в браузере.
2. Согласовать снимки Firebase Firestore **всех нужных коллекций и подколлекций**, Authentication, индексов, реально опубликованных rules, Storage и ссылок на внешние ресурсы. Дамп должен сохранять типы Firestore.
3. Для Sanastoyhteisö дополнительно включить Cloudflare Worker/D1, Google Sheets и локальные данные пользователя (локальные данные — через явную выгрузку с устройства, нельзя скачать чужой browser storage).
4. Для Velar Dream дополнительно включить каталог Studio, обложки, фотографии, приватные фонограммы в Drive, внешние метаданные и существующие Apps Script, где есть разрешение.
5. Серверное сохранение в приватный Google Drive Velar → WEBSITE_BACKUPS → Backup через OAuth/service account с минимальными правами. `drive.file` и scoped grants; не помещать refresh token в frontend.
6. На сайте в разделе «Данные» включить кнопку только когда сервер готов и валидируется реальная полнота; иначе показывать точное «неполная копия».
7. Архив: `manifest.json` (дата UTC, sha коммита, проверенные счётчики, схемы, недоступные компоненты), независимые снимки каждого хранилища, checksum для каждой части, инструкции по восстановлению. Разделять публичный и зашифрованный персональный payload.
8. Проводить restore drill в изолированных проектах. Нельзя писать «восстанавливается полностью», пока не прошёл тест и сравнение количества данных.

## Безопасность
GitHub Actions code snapshot **не может** и **не должен** притворяться полной резервной копией.
Не класть архивы с персональными данными в публичный GitHub и GitHub Pages, не возвращать приватные записи через общедоступный веб-роут.

ЗАВЕРШИЛ: создана техническая основа code snapshot в отдельной ветке.
НЕ ЗАВЕРШЕНО: единый полный ZIP, приватный экспорт облачных данных, автоматическая загрузка Google Drive, UI-кнопка, тест полного восстановления.
