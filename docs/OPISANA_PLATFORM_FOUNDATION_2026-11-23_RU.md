# OPISANA — архитектура образовательной платформы
Дата: 2026-11-23
Статус: **первый безопасный фундамент**, не коммерческий запуск и не полноценная LMS.

## Решение по бренду и домену
- Пока используем действующий сайт Sanastoyhteisö 3.0: `sanastoyhteiso.github.io`.
- «Opisana» и `opisana.fi` — будущий бренд и желаемый домен, но **доступность и покупка домена не подтверждены**.
- Ребрендинг, перенастройка Firebase Authorized Domains, OAuth redirect, индексация и редиректы — отдельный релиз после регистрации; менять базовый адрес сейчас не нужно.
- Существующие слова, результаты, V3 IndexedDB и пользовательские аккаунты сохраняем без миграции до проверенного плана.

## Проверенный аудит текущего состояния
1. `admin/index.html` и `admin/admin-page.js` — существующий закрытый админ-кабинет; доступ требует `emailVerified` и серверно выданного Firebase custom claim `admin === true`. Сейчас основной функционал — диагностика/мониторинг; вкладка обновлений намеренно заблокирована.
2. `family.js` — Google Authentication, UID-изолированное старое локальное хранилище; часть данных синхронизируется через `community.js`; V3 отдельно реализована в `v3-sync-release.js` и IndexedDB shadow.
3. `app.js` — текущие словарь, карточки, тесты, экзамен, личные слова и т. д. Пункты `data-view` заданы в HTML.
4. Не обнаружена действующая система учебных организаций, групп, поручений преподавателей, прав на обучение и коммерческих лицензий. Недопустимо изображать эти возможности работающими.

## Фаза 0 — безопасные разделы в отдельной ветке
- `/cabinet/`: первый кабинет учащегося; требует подтверждённого Google-входа; **только чтение** старых локальных результатов, строго для текущего UID. Нет чтения прогресса других учащихся, записей в Firebase и мутаций.
- V3-данные в IndexedDB и облачные события ещё не суммируются этим кабинетом. Отсутствие данных показано как «данные не найдены», а не как «0%».
- `/admin/layout/`: владелец может подготовить порядок, группировку и видимость пунктов меню, а также самостоятельно создавать/редактировать/удалять **локальные неопубликованные** черновики общих слов (FI/RU, необязательный EN, тема); их можно скачать JSON. Изменения хранятся только в браузере владельца; доступ требует тот же подтверждённый `admin` claim. Личные слова учащихся не затрагиваются. Публикация в общий словарь ещё не подключена.
- **Ни одна черновая настройка не применяется к `index.html`, текущей навигации или правам учащихся.** Предварительные UI-страницы не включены в основное меню.

## Рекомендуемая модель ролей
1. `owner` — владелец; финансы, лицензии, публикация, управление учётными записями персонала. Начальное доверенное право — server-issued Firebase `admin: true`, затем отдельная серверно контролируемая роль.
2. `editor` — редактор контента, может создавать и редактировать общие слова и учебные темы; не видит личных результатов учеников.
3. `teacher` — управляет **только назначенными группами**, своими курсами, заданиями и агрегированными/разрешёнными результатами по назначенным учащимся.
4. `student` — видит только собственные задания, слова и учебный прогресс.
5. `guest` — лишь доступные без подписки материалы.

**Нельзя** выдавать права учителя/владельца через localStorage, e-mail-домен или JS-переключатель. Вся защита обеспечивается backend и Firestore Security Rules; административный UI сам по себе никогда не является границей безопасности.

## Предлагаемая структура данных (ещё не развёрнута)
- `institutions/{id}`: название и статус лицензии, минимальные публичные сведения.
- `institutions/{id}/members/{uid}`: назначенная сервером роль, основание доступа, срок, дата изменения.
- `courses/{id}`: ID учреждения, учебный план, список опубликованных модулей.
- `courses/{id}/groups/{id}`: группа и состав (доступ только преподавателю группы, администратору организации и самим участникам с ограничениями).
- `assignments/{id}`: курс, группа, ссылки на материалы, дедлайн, автор, статус публикации.
- `users/{uid}/assignment_results/{id}`: индивидуальное состояние, доступ учащемуся и только уполномоченному преподавателю своей группы.
- `users/{uid}/progress/... `: остаётся частным; V3 данные читаются через проверенную текущую модель до миграции.
- `catalog_terms/{id}`: общий учебный словарь с черновиком, проверкой, публикацией, версиями и архивом; личные слова `users/{uid}` **никогда** не публикуются без отдельного согласия.
- `platform_config/navigation`: опубликованная структура меню с версией, ролью, видимостью и безопасным откатом; только серверно подтверждённый owner может публиковать.
- `audit_log/{event}`: серверная запись, кто и когда менял содержание, лицензию, публикацию или роли; без токенов, приватных ответов или данных пациентов.

Перед любыми write-операциями необходима отдельная проверка актуальных **развёрнутых** правил Firestore и emulator tests, включая отрицательные сценарии для другого UID, ученика без группы, отозванного преподавателя и истёкшей лицензии.

## Управление по разделам в конечной админке
| Раздел | Будущие настройки |
| --- | --- |
| Общие | Бренд, языки, навигация, порядок, предварительный просмотр, откат |
| Словари | Добавить/исправить/архивировать/опубликовать слово; импорт CSV, проверка дублей, редактор |
| Учебные темы | Категории, уроки, материалы, видимость по роли и курсу |
| Карточки / тесты / экзамен | Включение, режимы, параметры заданий и отчётности |
| Преподаватели | Роли, организации, группы, учебные планы и задания |
| Учащиеся | Лицензии/доступы, только разрешённая сводка по назначенной группе |
| Подписки | Тарифы, организации, оплаченные места, даты действия; серверная проверка |
| Система | Ошибки, резервные копии, аудит, staged releases и откат |

Показ/скрытие кнопки в браузере **не ограничивает** доступ к данным. Feature flags должны проверяться при доступе к серверному ресурсу и в API; скрытие пунктов меню — лишь отображение.

## План следующих этапов
1. Провести двухустройственное тестирование новых закрытых страниц и их локализации; оставить рабочий сайт неизменённым.
2. Объединить отображение V3 IndexedDB/облака и старой истории в одно **серверно подтверждаемое**, строго UID-изолированное представление прогресса. Не складывать события с одним и тем же ответом дважды.
3. Ввести серверную систему ролей учреждений, Firestore Rules и контракт API с тестами запрещённых сценариев.
4. Добавить полноценный контент-редактор с жизненным циклом черновик → проверка → публикация → откат; отдельно импорт слов.
5. Добавить группы/задания и преподавательский кабинет с контролируемым доступом к результатам.
6. Только после успешного пилота: оплата, лицензии школ, мобильные приложения, домен `opisana.fi`.
7. Проверить права на источники контента, GDPR, удаление/экспорт данных учащихся и правовые условия для образовательных организаций.

## Инварианты перехода
- Продолжает работать существующий сайт и V3-синхронизация.
- Сохранённые слова и результаты не сбрасываются и не пересоздаются по умолчанию.
- Нет публичного списка email учеников или доступа преподавателя к чужим данным.
- Нет серверных ключей в GitHub / браузере и нет клиентского самостоятельного назначения ролей.
- Любое изменение структуры сайта публикуется только после проверки, с журналом версий и кнопкой отката.
- Домены и платные функции не требуются для фазы 0.
