- Пользователь прислал два скриншота рабочего сайта с подтверждённым Firebase email, строкой `Настройки пока не загружены из облака: Quota exceeded..` и кодом `HTTP 429` в разделе «Участники сообщества». Проект Firebase: `riveria-sanasto-community-test`, конфиденциальные UID, email, токены, ответы и личные словари не сохранять в GitHub.
- Исходный main: `9b6ac5bced0fcf0eff3e7606b4d6ba69deb71636`. Резервная ветка `backup/pre-firestore-quota-run168-20261108`. Рабочая `fix/firestore-quota-run168-20261108`.
- Аудит: `community.js` вызывает Firestore REST `documents:runQuery` для `users`; `account-settings.js` выполняет `GET users/{uid}` + `GET settings/{uid}` при входе и после возвращения на вкладку/окно каждые 30 секунд. При неуспешном `refreshUsers` пустой экран «Пока нет публичных профилей» не отличает настоящую пустоту от недоступного сервера.
- По документам Google HTTP 429 / RESOURCE_EXHAUSTED означает ограничение квоты/частоты, но без метрик Firebase нельзя утверждать, какая именно квота исчерпана. Firestore бесплатные чтения: 50 000/день, записи: 20 000/день; лимит сбрасывается около полуночи Pacific. Нельзя менять тариф для «исправления».
- План: общий проектный (без UID) бережный браузерный backoff после подтверждённого HTTP 429; ограничить частоту фонового чтения настроек, обеспечить понятный статус и незатирание локальных данных; в списке пользователей не выдавать `HTTP 429` за отсутствие людей; без автоматических бесконечных повторов и без хранения в кэше чужих профилей; тесты на повторные запросы, отсутствие лишних записей, старую версию Safari и отсутствие персональных данных.
- Не менять Firestore Rules/Auth/права/IAM, Firebase тариф, учебный прогресс, персональные результаты, V3-механизм и дизайн. Никакие реальные профили не читать/писать. Подготовить отдельный PR и CI, затем безопасно опубликовать только после проверок в рамках ранее согласованного автономного процесса.
