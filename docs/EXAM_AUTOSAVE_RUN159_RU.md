# RUN-20261108-159 — сохранение попытки экзамена при уходе со страницы

## НАЧАЛ — 08.11.2026 Europe/Helsinki
Владелец обнаружил реальную проблему: начал 40-вопросный экзамен, ответил, перешёл на следующую страницу, затем случайно ушёл в другой раздел и при возвращении попытка началась заново. Это недопустимо для длинного экзамена.

Работа продолжается в отдельной ветке `fix/answer-feedback-run158-20261108`, вместе с незавершённым UX-исправлением RUN158; оба изменения попадут в один безопасный PR с отдельными журналами. Резерв `backup/pre-answer-feedback-run158-20261108`. Основной сайт не менять, пока не пройдут проверки.

**Требуемое поведение:**
- после каждого ответа и каждого перехода «Следующий» сохранять точный порядок 40 вопросов, выбранное направление, ответы, полученные оценки и текущую позицию;
- возврат после просмотра другого раздела и после перезагрузки браузера восстанавливает ту же страницу (например, 17/40), с сохранёнными предыдущими ответами;
- не показывать ключи до окончания экзамена; финальный результат также восстанавливается;
- новая попытка удаляет **только** её сохранённое состояние, а не словарь, пользовательские отметки, Firebase или кэш;
- состояние сохраняется в отдельном localStorage-ключе с namespace конкретной учётной записи `RS_FAMILY.storageKey(...)`; не передавать результаты в Firestore, не изменять `rs_scores_v1`, не пересекать аккаунты;
- при недоступности локального хранилища явно предупредить пользователя. Это локальное восстановление на текущем устройстве, не облачная синхронизация.
- валидация сохранённого состояния, безопасная обработка повреждённой записи и совместимость ES5/iOS12.

Проверить сценарии: ответ→следующий→другая вкладка сайта→возврат; перезагрузка страницы; 1/40, 17/40, 40/40 и результат; направление не меняется после первого ответа; новый экзамен сбрасывает только попытку; безопасность разных аккаунтов, запись недоступна и не меняет старые scores. Довести RUN158 и RUN159 до CI 3/3, Pages 3/3, двух журналов ЗАВЕРШИЛ и комментария в Issue №10.

Повреждённые данные не ломают приложение; невозможность записи в localStorage явно показывается предупреждением на странице.

**Ограничение:** это не облачная синхронизация. На другом телефоне/браузере, после удаления данных сайта, в приватном режиме с очисткой истории или при запрете хранилища сохранённая попытка может быть недоступна. Неподтверждённое переключение ответа до кнопки «Подтвердить» не учитывается, сохранение вызывается после подтверждения.
